# Tolerant mode

LaTeX copied from other tools is often broken: OCR noise, copies from HTML editors, JSON escapes that were never undone, double scripts. TeX refuses all of it. By default mathra **draws what it can and records a warning** for each problem. With `--strict` (CLI) or `Options { strict: true, .. }` (library), it refuses like TeX.

Warnings show up in `--explain`, on the CLI's stderr, in `Output::warnings` and inside the SVG, as `<mathra:warning rule="…">` in `<metadata>`. In `--batch` mode the line says `warning` instead of `ok`.

| Rule | Problem | What mathra does |
|---|---|---|
| E-REC-1 | Unknown command | If it is `\n` before a known relation (`\nlesssim`), reads it as its negation, `\not\lesssim`. If it starts with a known command (`\vertA`), reads it as `\vert A`. If it is a backslash before a symbol (`\5`), drops the backslash. Otherwise writes the name in red. An unknown chemfig arrow type is drawn as `->`, and TikZ other than `\draw` inside `\chemmove` is ignored. An unknown siunitx unit (`\SI{3}{\furlong}`) is written by its name. A math command or a math-only environment in text (`\text{\mathrm{V}}`, `\text{\begin{pmatrix}…}`, L-TXT-2) is read as math. A macro that never stops expanding is discarded, with a single warning. |
| E-REC-2 | Leftover JSON escape (`\n`, `\u00b2`); a control character in place of a backslash (`\frac` stored in JSON or in a program string without escaping); a Unicode superscript or subscript right after `^` or `_` (`\text{cm}^²`, `a_₂`), pasted from an editor | A control character in place of the backslash is rebuilt as the command when it and the whole run of letters after it make a known command (form feed + `rac` is `\frac`, line feed + `eq` is `\neq`), KaTeX's texvc aliases aside (`\th`, `\rarr`, `\real`…, which ordinary text after a tab makes); otherwise it is a space. A form feed, backspace, vertical tab or bell is always read this way. A real tab or line break is whitespace, as in TeX, and is read this way only when the input looks JSON-decoded: every tab and line break stands right before a letter (none ends a line before a symbol or a space, makes a blank line or indents the next one; the whitespace that ends the input aside), and no command starting with `n`, `r` or `t` kept its backslash (JSON would have eaten that one too: `\to` becomes tab + `o`). So `a \to`, line break, `u b` is `a → u b`, and a tab before `h(x)` is a space, not `\th`. Leftover escapes: `\n` and `\r` become a line break (a space), `\t` a space, and the warning names the escape read; `\uXXXX` becomes the character. An input with a real tab or line break shows no `\n`, `\r` or `\t` escape (a JSON string never has one): there `\nb` is an unknown command. Otherwise, an unknown command `\n…`, `\r…` or `\t…` is read as such an escape only when: the letter stands alone (`x\n2`, `a\n\frac…`); or one or two letters follow it (`x\nb`, `a\tx`) and the name is not a LaTeX text command (`\th`, `\ng`, `\rq`); or three or more letters follow it and the input, as it came, shows another escape that cannot be a command: `\n`, `\r` or `\t` before something that is not a letter, `\"`, or `\u` and four hexadecimal digits (`a = 1\n b = 2\nwhere`). Otherwise the name is a command mathra does not know (`\real`, `\rArr`, `\rowcolor`, `\numberwithin`): E-REC-1, with its first letter kept. The rule was set against the command lists of KaTeX and MathJax: every name there that the old rule split (21, from `\natnums` to `\th`) is E-REC-1 now. A superscript or subscript character after `^` or `_` is read as its plain character (`^²` as `^2`, `_₂` as `_2`, a run as a group: `^⁻¹` as `^{-1}`), so it is not shrunk and raised twice; without `^` or `_` (`x²`) it is drawn as it is, with no warning. The negations amssymb defines (`\nleq`, `\nsim`, `\nRightarrow`…) are known commands and never read this way. |
| E-REC-3 | Double script (`x_1_2`, `\text{O}^+_{(aq)}` after `_4`); a script mark as the argument of a script (`y__k`, `x^_2`) | The second script attaches to an empty base, as if the author had written `{}`; a mark that is the argument of a script is drawn as that script (`y__k` is y with the subscript `_`, then k). |
| E-REC-4 | Unbalanced braces; in a chemfig structure, an unbalanced branch `(`, bracket or ring | A stray `}` is ignored; an unpaired `{`, `(` or `[` is closed at the end. |
| E-REC-5 | Unpaired `\left`, `\right`, `\begin`, `\end`, `\schemestart` | `\left` without `\right` closes with an empty delimiter; a lone `\right` draws its delimiter; `\end` without `\begin` is ignored. |
| E-REC-6 | Unknown environment | Read as a centered table, with whatever cells and rows it has. |
| E-REC-7 | Missing argument (`\frac{1}`, `\xrightleftharpoons`) | The argument is left empty. |
| E-REC-8 | Character the font lacks, and no fallback font has (`Options::fallback_fonts`, S-SVG-5) | Draws a box (□). In strict mode, refused (`Error::MissingGlyph`). A character a fallback font has is drawn from it, with no warning, in both modes. |
| E-REC-10 | MathML: unknown element or named entity, element with the wrong number of children (`<mfrac>` with one) | An unknown element's children are read as a row; an unknown entity is dropped; a missing child is left empty. Content MathML outside the subset read (`spec/input.md`) is reported as such, its operands read as a row. Broken XML is an error in both modes: there is no tree to recover. |
| E-REC-9 | Others: unescaped `%` (a comment to the end of the line in TeX, but `15%` pasted into an equation almost always means a percent sign), unpaired `$` in `\text`, a `$` in the middle of the equation (`a + b $ = c`; the outer `$…$` are L-ENT-2), stray `#`, `&` outside an alignment (`u & v`), a row with more cells than its `array` declares, unknown `array` column, invalid delimiter, invalid color, a `\bbox` style or an `\enclose` notation or attribute mathra does not draw, control character (NUL, ESC…), `\divchave`/`\contaarmada` without integers or with a zero divisor, a siunitx value that is not a number (`\SI{x}{\meter}`, `\num{1.2.3}`), `\ang` with more than three parts, a character or bond `\ce` does not know; in chemfig, a stray character, a ring with more bonds than sides (or fewer than 3 or more than 40 sides), a `?` bond never closed, a mechanism arrow to a hook no atom has; `\ref`, `\eqref` or `\cite` with a key that has no number (L-ENT-5); a measure mathra cannot read in `\mskip`, `\hskip`, `\kern`, `\mspace` or `\hspace` (`\mskip 3furlong`, `\hskip\tabcolsep`); an assignment to `\thinmuskip`, `\medmuskip` or `\thickmuskip` | The character is drawn as is, or ignored (`%` is drawn as a percent sign, one warning per comment TeX would see; a loose `&` still separates the columns of an implicit alignment, and an extra cell is centered, the default); an invalid color is ignored; the calculation is written inline (`a ÷ 0`); the value is drawn as written; the extra ring bonds, the unclosed bond and the arrow are left out, an impossible ring is a hexagon; an unknown label is `??` (`(??)` for `\eqref`) and an unknown citation `[?]`, as on LaTeX's first run; an unreadable measure is no space, and the assignment is ignored. |

Comments are the one place where the two modes read valid LaTeX differently. In strict mode an unescaped `%` starts a comment, as in TeX: the rest of the line, the line break and the spaces that start the next line are dropped (`p = 15% \cdot q` is `p = 15`). The verbatim arguments of `\verb`, `\url` and `\href` keep their `%`, and `\%` is a percent sign in both modes. Tolerant mode draws the `%` and what follows, with the warning above.

Tolerant mode never changes the meaning of what was correct: every valid equation produces the same tree and the same SVG in both modes (test `t_tol_valid_equation_same_in_both_modes`).

## Limits

Some inputs are refused in both modes, because recovering would make no sense and going on would cost unbounded memory or stack:

| Limit | Value | Why |
|---|---|---|
| Nesting (`{`, `\frac`, `\sqrt`, `\left`, `^{`…) | 64 levels | Fits in a 1 MB stack (wasm, threads). |
| Macro expansions | 2,000, and the text does not grow past a multiple of the input | `\def\a{\a\a}` finishes. |
| `array` columns | 1,000 | `*{50}{*{50}{…}}` does not create millions of columns. |
| Digits in `\divchave`/`\contaarmada` | 30 | The arithmetic is exact in 128-bit integers. |
